## Round 19 — two main-thread blockers offloaded

### Round 19a — `save_profile()` off main thread

`_recognition_loop` previously called
`character_profile.save_profile(...)` inline once on first character
identity arrival. That function does a synchronous
`_read_settings()` + `_write_settings()` round trip against
`settings.json` (5-50 ms on slow disks). On the Tk main thread this
caused a one-frame UI hitch the user could see.

**Fix**: build the snapshot args at the call site, then start a
daemon thread (`sao-gui-save-profile`) that calls
`save_profile(...)` from background. Main loop returns immediately.

### Round 19b — `_stop_fisheye_overlay` async cleanup

`_stop_fisheye_overlay` was inline on main:
- `worker_thread.join(timeout=2.0)` — up to 2 seconds blocked.
- `gpu_win.destroy()` + `presenter.release()` — GPU teardown.
- Legacy Tk Toplevel `destroy()` — Tk-bound.

**Fix**: main thread does only the light Tk-bound work
(`_destroy_fisheye_hit_layer` + `_release_fisheye_input_zorder`)
plus flips the `running[0]` stop bit, then dispatches the heavy
cleanup to a daemon thread (`sao-fisheye-stop`). Legacy Tk Toplevel
destroy is re-dispatched back to main via `root.after(0, cb)` so
thread-affine widgets stay on the main loop.

## Round 20 — In-session roster sync throttle

`_push_packet_overlays` (called every `_recognition_loop` iteration,
~5 Hz) called `_sync_session_players_cache(gs, min_interval=0.05)`.
With the 200 ms recognition loop cadence and a 50 ms min interval,
the throttle never fired — every iteration ran the full
`bridge.get_players()` iteration + per-player merge (20-50 µs each
call).

**Fix**: bumped `min_interval` to **0.25 s** at the
`_push_packet_overlays` site. Session roster updates stay within
human-visible cadence (4 Hz), but the throttle now actually gates
the work. Other callers unchanged — user-driven panel refresh paths
(`_get_session_player_rows(sync=True)`,
`_toggle_session_players_panel`) continue to force fresh syncs.

## Safety / interface invariants

- All offloaded work preserves the original side effects (settings
  saved to disk, fisheye GPU resources released, session roster
  updated). The thread boundary only changes when the work runs,
  not what it does.
- No Tk operations were moved off the main thread. Legacy Tk
  Toplevel destroys are explicitly re-dispatched back via
  `root.after(0, ...)`.
- No feature flags, animations, or visuals touched.
- 4 module imports clean after each change (sao_gui, game_state,
  config, character_profile).
