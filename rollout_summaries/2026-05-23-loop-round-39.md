## Round 38 — Mass relocation of the remaining 8

Investigation revealed `sao_gui_dps.py` was a **hub module**:
imported by `sao_gui_hp.py`, `sao_gui_bosshp.py`,
`sao_gui_skillfx.py`, `sao_gui_buffmon.py`, AND
`gui_modules/sao_gui_alert.py` (which had just been moved in
round 37). It exports a cluster of shared Win32 ULW helpers
(`_ulw_update`, `_user32`, font helpers, GWL constants) that the
other overlay modules depend on.

This meant the remaining 8 files HAD to move together —
splitting the move across two rounds would have left
cross-imports broken between rounds. So round 38 became one

### Lurking old-path imports

A final repo-wide grep caught **4** straggler imports that
slipped through the initial scan:

| Location | Reason |
| --- | --- |
| `gui_modules/sao_gui_hp.py:717` | `import sao_gui_hp as _mod` (self-import for theme-driven setattr) |
| `gui_modules/sao_gui_skillfx.py:299` | `import sao_gui_skillfx as _mod` (same pattern) |
| `tools/bench_compose.py:172` | Developer bench script |
| `tools/spike_skillfx_ab.py:71` | Developer spike script |

The two self-imports inside `gui_modules/` would have raised
`ModuleNotFoundError` at runtime when the theme-switch code path
ran (only triggered on a setting toggle, so easy to miss). Fixed
by switching to `from gui_modules import sao_gui_X as _mod` /
`from gui_modules.sao_gui_X import ...`. The `tools/` scripts are
dev-only but updated for consistency.

### `XiaoACTUI.spec` updates

The 11 individual `'sao_gui_*'` entries in `LOCAL_HIDDENIMPORTS`
became `'gui_modules.sao_gui_*'`. Added a new
`GUI_MODULES_HIDDENIMPORTS = collect_submodules('gui_modules')`
catch-all and appended it to the `hiddenimports` line so future
additions to `gui_modules/` get bundled automatically (the
explicit list stays for clarity and to prove intent).

## What's intentionally NOT done

- `gui_modules/__init__.py` re-exports for the 11 new modules:
  the existing pattern only re-exports the small extracted
  classes (hotkey manager, panels, mixins). The 11 satellite
  modules are accessed via their full dotted path
  (`from gui_modules.sao_gui_X import Y`) which is explicit and
  doesn't need shimming. Adding 11 more re-exports would only
  reduce the path noise in 6-7 import sites in `sao_gui.py` —
  not worth the maintenance cost.
- Subdirectory grouping inside `gui_modules/` (e.g.
  `gui_modules/overlays/` vs `gui_modules/panels/`): would
  break the new dotted paths AGAIN and add no organizational
  value beyond what flat module names already convey.
