## Round 47 — `SAOPlayerGUIPanelsMixin`

A grab-bag mixin combining the remaining cohesive clusters that
didn't have a natural earlier home: Commander panel + panel
visibility + small settings toggles. 11 methods, ~188 lines net.

| Cluster | Methods |
| --- | --- |
| Commander | `_toggle_commander_panel`, `_push_commander_data` (48-line packet-driven snapshot builder, sig-cached at GUI level) |
| Panel visibility | `_toggle_hide_all_panels` (51-line snapshot+restore across 7 panel handles) |
| Recognition | `_toggle_recognition_menu` |
| Sound | `_toggle_sound_enabled`, `_adj_sound_volume` |
| Buffmon | `_toggle_buffmon_enabled` |
| Boss-bar mode cycle | `_cycle_boss_bar_mode` |
| Mem data source | `_get_mem_data_source`, `_cycle_mem_data_source` |
| Window | `_toggle_topmost` |

Why these belong together: every method here is a menu-handler or
small toggle that touches `self._cfg_settings_ref` and calls
`_refresh_menu_if_open()`. They share the **toggle → persist →
refresh** pattern.

Mixin imports: `perf_probe.probe as _probe` (for the
`@_probe.decorate('ui.commander_push')` decorator) and
`CommanderPanel` from the already-relocated
`gui_modules.sao_gui_commander`.

`_toggle_status_panel` (85 lines) was a tempting addition but
references 10+ module-level UI constants and helpers defined in
`sao_gui.py` (`_SAO_PANEL_HEADER_BG`, `_sao_panel_header`,
`_bind_panel_drag`, etc.). Moving it would require either pulling
those helpers along or importing them from `sao_gui` — the latter
creates a circular import since `sao_gui` already imports from
this mixin. Deferred to a later round when those helpers can
move together with the panel handlers.

sao_gui.py: 5077 → 4890 (-187).

## Round 49+ outlook

Remaining cohesive clusters in SAOPlayerGUI:

* **Panel UI helpers + `_toggle_status_panel`**: pull the
  `_SAO_PANEL_*` module-level constants and `_sao_panel_*` helper
  functions together with the status panel handler. ~200-300 lines
  but invasive (sao_gui module-level state).
* **Profile editor + about/help dialogs**: `_show_about`,
  `_edit_profile`, `_show_welcome_then_menu`. Smaller, simpler.
* **Updater integration**: `_check_for_updates_interactive`,
  `_update_listener`, `_build_update_menu_label` (already in Menu
  mixin), updater status panel handlers. ~150 lines.
* **HP overlay menu**: `_hp_overlay_on_menu`. Small.

After those, what remains in `SAOPlayerGUI` is mostly:
* `__init__` (long, hard to slice cleanly without breaking init order)
* Lifecycle (`_on_close`, `_finalize_close`, `_run_exit_animation`)
* Recognition / engine bring-up (`_start_recognition`,
  `_reconfigure_data_engines`, `_stop_recognition_engines`)
* Float-button construction + breath animation
* Module-level UI helpers (`_SAO_PANEL_*` constants,
  `_sao_panel_header`, `_apply_panel_style`, etc.)

The structural mixin work has largely accomplished the goal of
breaking the monolith. What remains is harder to slice — the
construction + lifecycle code is deeply coupled to instance
initialisation order.
