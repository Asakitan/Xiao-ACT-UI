## Round 15 post-cadence — `_row_independent_pct` signature trim

After round 4's cython migration of the inner per-row loop, the wrapper
kept two unused parameters (`hue` and `fill_hue_ref`) as
backward-compat placeholders. Single caller in `_detect_bar_pct`
already passes `None` for `hue`, so trimming the signature is safe:

```python
# Before:
def _row_independent_pct(hue, sat, val, hue_mask, fill_hue_ref, threshold): ...
row_median_pct = _row_independent_pct(None, sat, val, hue_mask, fill_hue_ref, threshold)

# After:
def _row_independent_pct(sat, val, hue_mask, threshold): ...
row_median_pct = _row_independent_pct(sat, val, hue_mask, threshold)
```

Verified: 12 module imports clean, `_row_independent_pct(60% mask)`
returns 0.997, `_detect_bar_pct(50% gold)` returns 0.498.

## Round 16 — BossRaidEngine entity-update throttle

`on_damage_event` previously called `_fire_entity_update_locked()` on
every damage event. That method rebuilt the full entity-list dict
(1-3 entities × 14 fields) and invoked the registered UI callback.
Under heavy combat (500-1000 events/sec) this burned **2.5-15 ms/sec**
on UI work the user can't perceive at that rate.

Refactor:
- Added `_entity_update_dirty: bool` and `_last_entity_update_emit_at:
  float` to BossRaidEngine state.
- `on_damage_event` now flips the dirty bit (O(1)) instead of
  rebuilding + firing.
- Existing `_run_loop` (4 Hz tick) drains the bit via a new
  `_maybe_flush_entity_update_locked()` that honours a 10 Hz emit cap.

Verified across 4 scenarios:
- 100 events → 0 callback fires (per-event path is bool-only).
- Manual flush → 1 fire.
- Second flush within 100ms throttle → still 1.
- Third flush past 100ms → 2 fires.

The `set_entity_role` (user-driven, rare) path keeps its direct fire
so manual role changes still propagate immediately.

## Round 17 — AutoKeyEngine `get_status()` deepcopy → `dict()`

`_status` is a flat 7-field dict of primitives (bool, str, float).
`copy.deepcopy` was equivalent to a shallow `dict(...)` copy but ~38x
slower. Same fix shape as round 10a's `hit_fx` cleanup.

- Old: 2605 ns/call.
- New: 68 ns/call.
- Verified: snapshot independence preserved (mutating the returned dict
  doesn't leak back into engine state).
