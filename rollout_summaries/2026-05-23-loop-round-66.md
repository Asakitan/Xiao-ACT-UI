## Round 64 — `SAOPlayerGUIPanelFxMixin`

The SAO HUD panel-fx shared scheduler — the bit that draws the
faint left/right ornamental sliders on every floating panel and
ticks them on one shared after(90 ms) loop. ~150 lines net out
(method bodies + 2 class attributes + 1 module-level helper).

| Item | Lines | Purpose |
| --- | --- | --- |
| `_sao_fx_panels` class attr (list) | 1 | Active panels registry — items are `(panel, body_cv, pw, ph)` |
| `_sao_fx_after_id` class attr (int / None) | 1 | Shared after() ID |
| `_make_sao_panel_hud` (module-level helper) | 22 | Lightweight Tk Canvas factory for the HUD layer |
| `_attach_sao_panel_fx` (instance method) | 62 | Register a panel: build HUD canvases, install sig cache, bind destroy auto-unregister, start the shared tick on first registration |
| `_sao_fx_shared_tick` (staticmethod, `@_probe`-decorated) | 75 | 90 ms shared loop: iterate active panels, compute coords via `_CY_UI.sao_fx_coords`, move Canvas items only when sig changed, re-schedule |

### Class-attr relocation

The 2 class attributes had been declared on `SAOPlayerGUIFloatHpMixin`
since round 56 — they were originally on SAOPlayerGUI proper and
got pulled along with the float-HP cluster as a happenstance.
Round 64 moves them to their proper home with the methods that
use them (PanelFxMixin). MRO lookup still resolves the
`SAOPlayerGUI._sao_fx_panels` references identically.

### `SAOPlayerGUI._sao_fx_*` → `type(self)._sao_fx_*` rewrite

`_attach_sao_panel_fx` and `_sao_fx_shared_tick` had explicit
`SAOPlayerGUI._sao_fx_*` class-attribute references throughout.
Rewriting them to `type(self)._sao_fx_*` (instance method) and
`type(self_ref)._sao_fx_*` (staticmethod with `self_ref` arg) lets
the mixin avoid importing the not-yet-defined SAOPlayerGUI class
while preserving semantics (writes still go to the SAOPlayerGUI
class via type() resolution).
