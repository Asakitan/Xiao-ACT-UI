## Round 32 — `SAOPlayerGUIStateMixin` (combat-lag surface)

The biggest extraction so far and the one that targets the user's
core complaint. Four methods that together make up the
state-pull + overlay-push pipeline move out:

| Method | Purpose |
| --- | --- |
| `_on_game_state_update` | GameStateManager listener — runs on bridge worker / recognition thread |
| `_apply_fast_state_update` | Main-thread continuation dispatched via `root.after(0, ...)` |
| `_push_packet_overlays` | **HOT PATH** — main-thread per-tick push (DPS / Boss HP / commander / HP overlay / SkillFX) |
| `_recognition_loop` | 200 ms Tk-after-driven main-thread loop that pulls game state |

This is the cluster the user calls out in the task ("能不放主线
程上的就不放主线程上"): `_push_packet_overlays` does all of:
* dirty-stream packet parse
* DPS event ingest
* Boss HP update
* commander roster refresh
* HP overlay GPU push
* SkillFX worker dispatch

…all on the Tk main thread, 5 times a second. With the cluster
now isolated in its own module, round 34 can introduce a
background snapshot worker queue without touching anything else.

**Encountered + fixed during extraction:** initial mixin module
raised `NameError: name '_probe' is not defined` because
`_push_packet_overlays` calls the perf_probe instrumentation
helper. Added `from perf_probe import probe as _probe` to the
mixin alongside `import threading`, `import time`, and the two
cython modules (`_sao_cy_packet`, `_sao_cy_uihelpers`).

## Round 34+ outlook — combat-lag fix is now actionable

Now that `_push_packet_overlays` lives in its own module with a
clear contract on what `self.X` it touches, the combat-lag fix
becomes a focused refactor inside one file:

**Plan**: introduce a packet snapshot queue (bounded, drop-oldest)
that a daemon worker consumes. Worker computes overlay deltas
(damage IDs, boss HP percent, commander roster diff) off-main,
then re-enters Tk via `root.after(0, apply_overlay_delta)` for
the actual widget mutations. The 5 Hz `_recognition_loop` no
longer does the heavy compute on main; it only kicks the worker.

Other future extractions (smaller, can wait):
- Menu mixin (SAO menu build + child-menu handlers)
- Fisheye mixin
- Boss-raid mixin
- Commander mixin

Final: PyInstaller spec `hiddenimports` for `gui_modules.*` so
dynamically-imported sub-modules are bundled by the build.
