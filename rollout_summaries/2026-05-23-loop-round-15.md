## Round 13 — `GameStateManager` snapshot via `copy.copy`

`GameStateManager.update` and `load_cache` build a fresh `GameState`
snapshot via a 47-field dict-comp + dataclass `__init__`:

```python
snapshot = GameState(**{
    f.name: getattr(self._state, f.name)
    for f in self._state.__dataclass_fields__.values()
})
```

Profiled 4 alternatives over 50k iterations:
- Original dict-comp: 3.55 µs/call
- `vars()` + dict expansion: 1.43 µs/call
- **`copy.copy(self._state)`: 1.04 µs/call** (winner)
- `dataclasses.replace`: 5.24 µs/call (slowest)

Replaced both snapshot sites with `_copy.copy(self._state)` (imported as
`_copy` to avoid colliding with any local `copy` symbols). Verified:
- Snapshot independence preserved (mutations to the snapshot don't
  leak back to `_state`).
- Shallow-copy semantics for list fields (`skill_slots`, `self_buffs`)
  match the prior dict-comp behaviour — both shared the same list
  references, so callers see no difference.

`update()` end-to-end now ~1.89 µs/call (was ~3.5 µs before). At
~160 update calls/sec heavy combat (60 fps recognition + ~100 bridge
events/sec) this saves ~400 µs/sec on the lock-held path inside the
GameStateManager.

## Round 14 — `packet_bridge._publish_player_update` caching

The bridge publish called `self._use_packet_source(component)`
**nine times per publish** for the same five components (identity,
level, hp, stamina, skills). Each call walked through `Settings.get` +
a string-compare, ~500 ns each — totalling ~4.5 µs per publish in
redundant settings dispatch.

Cached all five results once at the top of the function:

```python
use_identity = self._use_packet_source('identity')
use_level    = self._use_packet_source('level')
use_hp       = self._use_packet_source('hp')
use_stamina  = self._use_packet_source('stamina')
use_skills   = self._use_packet_source('skills')
```

Replaced the rest of the function's references with the cached
locals. **Verified by grep**: `self._use_packet_source(` count
inside `_publish_player_update` dropped from 9 to 5 (only the top
caching block remains).

Also cached `self._state_mgr.state` once (a `@property` that locks on
every access). The function previously dereferenced it 3 times
(stamina_max defaults x2, skill_slots diff x1); now it's read once
into `_state_snap`.

**Saving: ~2-2.5 µs of Python dispatch + 2 fewer lock acquires per
publish.** At ~12 bridge events/sec heavy combat ≈ ~30 µs/sec on the
bridge thread.
