## Round 9 post-cadence — `percentile_slice_f32` (already in v3.1.4)

Already covered by round 9, but worth keeping in this MD because the
**.pyx changes were committed in `b19c443`**. The cython kernel folds
three `np.percentile(slice, q)` calls per bar into a single insertion-
sort + linear-interpolation pass over a small (~50 element) float64
buffer. **27x speedup**: 26.9 → 1.0 µs/call. End-to-end
`_detect_bar_pct` now **0.204 ms/call** (vs. ~0.9 ms baseline).

## Round 10 — dps_tracker micro-opts

Two small fixes in `dps_tracker.py`, both on per-UI-poll or per-event
hot paths.

### Round 10a — `hit_fx` deepcopy → `dict()`

`_build_snapshot_locked` previously did `copy.deepcopy(self._last_hit_fx)`
on every snapshot. `_last_hit_fx` is a flat 6-field dict of primitives
(`seq` / `uid` / `name` / `amount` / `tier` / `generated_at`) — a
shallow `dict(...)` copy is equivalent and ~10x faster.

### Round 10b — `_process_event` inline cython + cached skill table

Removed the `_resolve_skill_key(event)` wrapper call from
`_process_event` and inlined a direct `_CY_COMBAT.resolve_skill_key`
call with the cached module-level `_SKILL_LEVEL_TO_EFFECT` table. Saves
one Python function dispatch per damage event; `_process_event` end-to-
end now ~1.3 µs/call (~1.3 ms/sec on the bridge thread at 1k events/sec
heavy combat).

## Round 11 — auto_key engine config cache

The biggest single-round win in a while.

`AutoKeyEngine._tick` runs at ~20 Hz and previously called
`load_auto_key_config(self._settings, ...)` → `normalize_auto_key_config(raw, ...)`
on every tick. `normalize_auto_key_config` deep-coerces every profile,
every action, every condition, plus rebuilds the search-query block —
~17.4 µs per tick.

**Fix**: cache the normalized config in `AutoKeyEngine`, keyed by:
- `id(self._settings.get("auto_key", {}))` — picks up
  `settings.set("auto_key", ...)` calls (the UI's edit/save path).
- A small tuple of identity fields from the game state
  (`player_id`, `player_name`, `profession_id`, `profession_name`) —
  picks up login / map-switch identity changes.

`AutoKeyEngine.invalidate()` (called from the UI on save) drops the
cache too, so any code path that mutates the config in place still
triggers a re-normalize on the next tick.

- **~75x speedup**: 17.4 µs/tick → 231 ns/tick on cache hits.
- 4 cache-invalidation scenarios verified (fresh start, identical input
  reuse, `settings.set` triggers fresh normalize, identity change
  triggers fresh normalize).

This is the first "non-cython" optimization landed in the loop. The
Python-level cache makes a bigger impact than another small cython
kernel would have.
