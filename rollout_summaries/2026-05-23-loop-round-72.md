### `packet_bridge.py` intentionally NOT changed

`packet_bridge.py` still has a lazy `from mem_probe.unified_source
import UnifiedDataSource` inside `_start_memory_source`. The runtime
behaviour is **already graceful**:

* `data_source='tcp'` (default) → never touches `_start_memory_source`,
  no `mem_probe` reference resolved at runtime.
* `data_source='memory'` → strict mode; lazy import fails, returns
  False, `_error_msg` reflects it, bridge bails (correct: memory
  mode is broken since deletion).
* `data_source='hybrid'` / `'auto'` → fallback to TCP on import
  failure (correct: gracefully degrades).

Removing the `_start_memory_source` code path would mean users on
the (broken) `mem_probe` opt-in path get a different error
message, not a behavioural improvement. Leave it.

## Round 71 — `_set_process_app_id` NameError fix + dead code

### Latent bug introduced in round 68

When round 68 extracted `_set_icon` into `SAOPlayerGUIMiscMixin`,
the method body references `_set_process_app_id('sao.auto.game.ui')`
as a bare name. The function was defined at module level in
`sao_gui.py`, NOT imported into the mixin module — calling
`_set_icon` from a SAOPlayerGUI instance (which `__init__` does
via `self._set_icon()` on every startup) would raise
`NameError: name '_set_process_app_id' is not defined`.

Validated the gap by running `inspect.getsource(MiscMixin._set_icon)`
+ `grep _set_process_app_id gui_modules/sao_gui_misc_mixin.py` —
zero matches in the mixin's import block, but the call site uses
it.

### Fix

1. Move `_set_process_app_id` to `gui_modules/sao_panel_ui.py`
   alongside the other Win32 helpers (4 already there from
   round 59).
2. Delete the duplicate definition from `sao_gui.py` (line 168).
3. Delete the duplicate definition from `sao_webview.py` (line
   107) — there were two identical copies of the same shell32
   call. Replace with `from gui_modules.sao_panel_ui import
   _set_process_app_id`.
4. Add `_set_process_app_id` to the panel-UI block re-import in
   `sao_gui.py` so the still-resident `__init__` call at line 272
   keeps working.
5. Import `_set_process_app_id` in `gui_modules/sao_gui_misc_mixin.py`
   alongside `_apply_window_icon` (the other bare-name reference
   in the same `_set_icon` method body).

### Dead code: `_get_hp_pil_font`

`sao_gui.py` line 199 defined a PIL font cache helper that was
never called from anywhere (repo-wide grep returned only the
definition site + a historical mention in the round-69 MD). Pure

`sao_sound.py` (`get_sao_font` / `get_cjk_font`) and in the
gui_modules overlay files; this one was an orphan.

sao_gui.py: 524 → 507 (-17).
