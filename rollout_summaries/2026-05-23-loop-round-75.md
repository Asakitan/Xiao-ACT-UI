## Round 73 — AST audit + 9 NameError bug fixes

### The audit

Python AST walk on each `gui_modules/sao_gui_*_mixin.py`:

1. Collect names imported at module level (`Import` + `ImportFrom`
   nodes).
2. Collect names defined as nested `FunctionDef` / `ClassDef`
   inside method bodies (closures).
3. Walk all `Call` nodes; for each `Name`-style callee, flag if the
   name isn't in {builtins ∪ imported ∪ nested defs ∪ a small
   curated whitelist of common variable names like `self`, `tk`,
   `np`, etc.}.

False-positive sources the audit doesn't track:
* `for X in (...): X()` — loop variables. Caught 4 cases:
  `_g`, `_cap_fn`, `_grab` in fisheye + float_hp. All verified
  manually as closures.

### The 9 real bugs

Each one is a function the original `sao_gui.py` had at module
level, NOT carried over into the mixin's import block during the
round-N extraction. Would `NameError` at first call:

| --- | --- | --- |
| `sao_gui_float_hp_mixin.py` | `_perf_gauge` | `perf_probe.gauge` |

| `sao_gui_fisheye_mixin.py` | `_phase_trace` | `perf_probe.phase` |

### Why these weren't caught earlier

The mixins were extracted via "method body extraction" — copy the
function body, paste into a new mixin file, delete from
sao_gui.py. The script that did this for the bigger mixins
(rounds 65 link-animation, 50 status-updater, 56 float-hp, 41
fisheye) DIDN'T track which module-level helpers each block used.

Module-level imports were added based on what I **manually**
identified at extraction time — but in mixins with 9-20 methods
spanning hundreds of lines (status-updater 857, link-animation
911, fisheye 1421), inspection missed some references.

The audit catches them all in O(N) walk per mixin. Should have
been part of the extraction pattern earlier.

Also attempted a runtime construction smoke test (`SAOPlayerGUI()`)
but it crashed at the `pynput` module's Win32 message loop on
Python 3.11:

```
ctypes.ArgumentError: argument 1: <class 'TypeError'>:
    expected LP__PUMP_MSG instance instead of pointer to MSG
```

This is a known incompatibility between modern `pynput` versions
and Python 3.11's stricter `ctypes` validation — unrelated to
the refactor. The user runs the actual app and won't hit this in
a real Win32 GUI environment (different ctypes init path).

### Duplicate `_user32` declaration check

8 files declare `_user32 = ctypes.windll.user32` at module level
(`gpu_capture.py`, 6 files in `gui_modules/`, `overlay_render_worker.py`,
`sao_gui.py`). Since `ctypes.windll` caches DLL handles, all 8
reference the same underlying object — they're not duplicating
runtime state, just re-declaring the alias. Each module being
self-contained is the better design; no consolidation needed.
