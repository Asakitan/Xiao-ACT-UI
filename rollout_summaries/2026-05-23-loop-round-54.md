### `__file__` fix

`_reconfigure_data_engines` originally located the
`skill_names.json` bundle via:

```python
_skill_json = os.path.join(
    os.path.dirname(os.path.abspath(__file__)),
    'assets', 'skill_names.json',
)
```

This worked when the method lived in `sao_auto/sao_gui.py` because
`__file__` resolved to the project root. After moving to
`gui_modules/sao_gui_engine_lifecycle_mixin.py`, `__file__` would
resolve to the `gui_modules/` subdirectory and the path would be
wrong.

Fixed by switching to `resource_path('assets', 'skill_names.json')`
from `config` — `resource_path()` consults the same BASE_DIR /
BUNDLE_DIR fallback that the rest of the app uses for asset
lookup, so the path resolution is now correct regardless of where
the calling module lives.

## Round 55+ outlook

What remains in `SAOPlayerGUI` after this cadence is mostly
lifecycle code that's tightly coupled to `__init__`:

* `__init__` itself (long, hard to slice without breaking init
  ordering)
* `_finalize_close`, `_run_exit_animation`
* Float-button construction + breath animation (`_start_float_breath`,
  `_lift_float_loop`, etc.)
* Misc small helpers: `_setup_hotkeys`, `_on_close`,
  `_update_float_title`, `_update_float_status`,
  `_update_float_fname`, `_raise_panel_window`, etc.
* Packet event callbacks: `_on_packet_damage`,
  `_on_monster_update`, `_on_boss_event`, `_on_scene_change`
* `_send_linked_key`, `_should_show_sta_offline`,
  `_reset_sta_offline_state`, `_refresh_hp_layered`,
  `_hp_overlay_on_click`, `_hp_overlay_restore_position`,
  `_hp_overlay_hide`

The structural refactor goal — get a 9682-line monolith manageable
and break it into focused, named pieces — has been substantially
met. Future rounds extract smaller, less-cohesive clusters with
diminishing returns.

Plausible round-55+ candidates:
* **Packet event callbacks mixin**: ~150-300 lines, 4 methods.
  Tightly coupled to packet_engine but extractable.
* **Float-button + breath animation mixin**: ~200-400 lines.
* **Lifecycle mixin**: `_on_close`, `_finalize_close`,
  `_run_exit_animation` (very __init__-coupled).
