### `__file__` fallback fix

`sao_menu_hud.py` had a dev-mode `_BASE` fallback:

```python
_BASE = (
    getattr(sys, '_MEIPASS', os.path.dirname(sys.executable))
    if getattr(sys, 'frozen', False)
    else os.path.dirname(os.path.abspath(__file__))  # ← now wrong
)
```

After moving to `gui_modules/`, `__file__` resolves one directory
deeper than before. Replaced with a `dirname(dirname(...))` so the
dev fallback still points at the project root. The frozen path
(via `sys._MEIPASS` / `sys.executable`) is unaffected.

### Circular import fix

The move surfaced a latent import cycle:

```
sao_gui → sao_theme → gui_modules.sao_menu_hud
                      → gui_modules/__init__.py
                      → gui_modules.sao_gui_menu_mixin
                      → sao_theme.SAOPopUpMenu    ← partially-initialized!
```

The cycle existed because `gui_modules/__init__.py` was eagerly
importing every SAOPlayerGUI mixin, one of which (`sao_gui_menu_mixin`)
itself imports `sao_theme.SAOPopUpMenu`. Before round 61 nothing
else needed `sao_theme` to traverse `gui_modules/__init__.py`, so
the cycle slept. Once `sao_theme.py` itself imported from
`gui_modules.*`, the cycle woke up.

**Fix**: the mixin re-exports in `gui_modules/__init__.py` were
removed. The mixins are SAOPlayerGUI-internal — they're only
imported via the full dotted path (`from gui_modules.X import Y`)
in `sao_gui.py`. The re-exports were unused convenience. The
standalone helper classes that are actually imported as
`from gui_modules import X` (5 of them) stay re-exported.

### `type(self)._sao_fx_after_id` fix

`_finalize_close` directly referenced `SAOPlayerGUI._sao_fx_after_id`
(a class-level shared after-id for the panel-fx tick). When moved
to a mixin, the mixin can't reference the not-yet-defined
`SAOPlayerGUI` class without circular imports. **Fix**: replace
`SAOPlayerGUI._sao_fx_after_id` → `type(self)._sao_fx_after_id`
in the extracted block. Since `_sao_fx_after_id` is a class
attribute on `SAOPlayerGUI` itself (not on a mixin),
`type(self)._sao_fx_after_id` resolves identically via MRO/class-
attribute lookup. Same fix applied to the `getattr(SAOPlayerGUI, ...)`
call.

## Root `sao_*.py` remaining (intentionally not moved)

After round 61, the only `sao_*.py` files still at the repo root
are these 6 — each of which is structurally distinct from a
SAOPlayerGUI widget and shouldn't move:

* `sao_gui.py` — the main class entry point.
* `sao_theme.py` — the theme module (SAOPopUpMenu, SAODialog,
  SAOColors, etc.) that's imported by both `gui_modules/*` and
  external modules.
* `sao_sound.py` — global sound + font helpers.
* `sao_updater.py` — the auto-updater state machine.
* `sao_webview.py` — the entirely separate WebView UI.
* `sao_web_panel_common.py` — shared panel UI between SAO HUD and
  WebView UI.

Moving any of these would introduce new dependency cycles
(`sao_theme.SAOPopUpMenu` is the worst offender) or break the
"`sao_webview.py` is an independent entry point" contract.
