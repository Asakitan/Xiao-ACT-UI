## Round 59 — Win32 helpers + `_create_floating_widget`

### Phase 1: Move 4 Win32 helpers to `sao_panel_ui.py`

The four module-level Win32 helpers all manipulate Tk Toplevel
windows via the same `ctypes.windll.user32` + dwmapi APIs the
`_apply_panel_style` helper already uses. Natural cluster:

| Helper | Lines | Purpose |
| --- | --- | --- |
| `_get_icon_path` | 5 | Resolves `icon.ico` via `resource_path` |
| `_apply_window_icon` | 31 | iconbitmap + Win32 WM_SETICON for taskbar |
| `_set_clickthrough_style` | 16 | Win32 WS_EX_TRANSPARENT click-through |
| `_disable_native_window_shadow` | 11 | DWMNCRP_DISABLED for non-rect windows |

Total: 63 lines moved out of sao_gui.py. `gui_modules/sao_panel_ui.py`
grew from 195 → ~280 lines.

`sao_gui.py` keeps a single re-import line so callers that still
reference the unqualified names work transparently:

```python
from gui_modules.sao_panel_ui import (
    # ... existing panel-style helpers + constants ...
    _get_icon_path, _apply_window_icon, _set_clickthrough_style,
    _disable_native_window_shadow,
    # ...
)
```

### Phase 2: Move `_create_floating_widget`

The 131-line float-anchor Toplevel constructor that was previously
blocked. Appended to `SAOPlayerGUIFloatHandlersMixin`. Mixin imports
grew to include `tkinter as tk`, `ctypes`, `_apply_window_icon` +

`get_cjk_font` from `sao_sound`. The mixin also declares its own
module-level `_user32 = ctypes.windll.user32` handle (ctypes.windll

sao_gui.py: 2537 → 2347 (-190 net for round 59: 63 helpers + 131
method = 194 lines moved out; offset by a 4-line import expansion).

## What's left in `sao_gui.py` (2347 lines)

After 14 mixin extractions + panel-UI helper relocation, the
remaining lines are:

* `__init__` (long, tightly-coupled — instantiates engines, builds
  the float button, wires hotkeys, restores panels, etc.)
* `_finalize_close`, `_run_exit_animation`, `_on_close` —
  lifecycle teardown
* `_restore_panels` — restore floating panels on startup
* `_get_floating_windows` — enumerate all active panel windows
* Module-level imports + top-level helper functions
* `_sao_fx_panels` class-attr setup + `_sao_fx_shared_tick`
  staticmethod (panel-fx shared scheduler)
* `_close_finalized`, exit-animation state machines
* Module entry: `if __name__ == '__main__': SAOPlayerGUI().run()`

The remaining code is heavily `__init__` / lifecycle-coupled, hard
to slice without breaking init order. **The structural goal has
been substantially met.** Further extractions would yield
diminishing returns + significant risk.
