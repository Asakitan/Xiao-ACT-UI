## Round 1 — `compute_damage_id` migration

**Files**: `_sao_cy_combat.pyx`, `dps_tracker.py`, `build_cython_ext.py`,
`_sao_cy_combat.cp311-win_amd64.pyd`.

- Added two `cpdef` helpers to `_sao_cy_combat.pyx`:
  - `compute_damage_id(event, skill_effect_table) -> long long` — mirrors
    `dps_tracker._compute_damage_id` byte-for-byte with C-typed integer math
    via a new `_append_decimal_ll` inline helper.
  - `resolve_skill_key(event, skill_effect_table) -> long long` — does the
    `damage_id or skill_key or skill_id` fallback chain in one cython call.
- Rewrote `dps_tracker._compute_damage_id` to delegate to the cython call,
  collapsed the `_compute_damage_id(event) or _safe_int(...) or skill_id` line
  in `_process_event` to a single `_resolve_skill_key(event) or skill_id`.
- Dropped the `mem_probe._sao_cy_memscan` extension entry from
  `build_cython_ext.py` (mem_probe was already deleted from the working tree
  before this loop started) — wrapped it in an existence check so future
  re-introductions still build automatically.
- **Validation**: 8 parity cases against the original Python implementation
  (empty event, skill_id=0, damage_source∈{0,1,2}, table-hit / table-miss /
  hit_event_id padding) — all identical outputs. 12 module-level imports
  succeed without regression.
- **Micro-benchmark**: 546 ns/call for `compute_damage_id`, 217 ns/call for
  `resolve_skill_key`. At ~1k damage events/sec in heavy combat this saves
  ~1-2 ms/sec of Python dispatch overhead from the bridge thread.

## Round 2 — dirty-stream sub-field header consolidation

**Files**: `_sao_cy_packet.pyx`, `packet_parser.py`,
`_sao_cy_packet.cp311-win_amd64.pyd`.

- Added two helpers to `_sao_cy_packet.pyx`:
  - `parse_dirty_subfield_header(data, pos) -> (ok, new_pos, sub_field)` —
    parses the `[0xFFFFFFFE marker (4B)] [validation (4B)] [sub_field u32]`
    boilerplate that every CharSerialize dirty-stream branch starts with.
  - `try_read_le_u32_at(data, pos) -> (ok, value, new_pos)` — bounds-checked
    u32 read that does not raise; lets callers use a single guard line.
- Refactored 8 branches of `packet_parser._parse_dirty_stream` to use the
  new helper:
  - `field 2`  (CharBase)
  - `field 16` (UserFightAttr — HP/MaxHP/OriginEnergy)
  - `field 22` (RoleLevel)
  - `field 50` (SeasonCenter — outer + nested BattlePass)
  - `field 52` (SeasonMedalInfo — outer + nested CoreHoleInfo)
  - `field 56` (MonsterHuntInfo)
  - `field 61` (ProfessionList)
  - `field 102` (DeepSleep — also flattened a 3-deep `if pos + N <= len(data)`
    nest that was previously needed to stay inside the failure-safe path).
- Net effect: ~50 lines of boilerplate removed; ~16 pairs of
  `_CY_PACKET.read_le_u32_at` calls collapsed into 8 single calls.
- **Validation**: 6 parity cases for the header helper (valid / wrong marker
  / truncated / empty / offset), 4 for `try_read_le_u32_at`. Three end-to-end
  dirty-packet tests verify the CurHp (field 16/1), Level (22/1), and
  ProfessionId (61/1) branches still write the right `PlayerData` fields.
  All 12 module imports remain clean.
- **Micro-benchmark**: 176 ns/call for the new helper vs 373 ns/call for the
  equivalent Python-side `read_le_u32_at` triple — ~53% faster per branch.
  `_parse_dirty_stream` hits the pattern up to ~10 times per dirty packet.
