## Round 21 post-cadence — double-sync fix in `_refresh_session_players_panel`

`_push_packet_overlays` calls `_sync_session_players_cache(gs, min_interval=0.25)` (round 20), then conditionally calls `_refresh_session_players_panel()` when the menu is visible. Inside that function, line 4705 used to call `self._sync_session_players_cache(gs)` **without** `min_interval`, defaulting to `0.0` (no throttle). So when menu was visible, every recognition_loop iteration paid the full `bridge.get_players()` iteration twice.

**Fix**: passed `min_interval=0.25` to the inner sync too. The 0.25 s gate now actually engages on both call paths.

## Round 22 — `_lift_float_loop` cadence 150 ms → 250 ms

`_lift_float_loop` keeps the floating HP/status badge on top of the SAO menu by calling `self._float.lift()` (Win32 `SetWindowPos`) on a periodic loop. Cadence was 150 ms (6.7 Hz). Bumped to **250 ms (4 Hz)**.

The user can't perceive the extra 100 ms before the badge is re-lifted above the menu, but the per-second `SetWindowPos` call count drops ~40 %, saving ~100-300 µs/sec of main-thread work whenever the SAO menu is open. The loop is dormant when the menu is closed.

## Round 23 — `_on_game_state_update` identity-dedup for self_buff overlay

`_on_game_state_update` is the GameStateManager listener; it fires on every `state_mgr.update(**kwargs)` call (~30-60 Hz under combat). Previously it unconditionally called `ov.update_buffs(list(getattr(gs, 'self_buffs', []) or []), ...)` for the self-buff overlay, even on the many ticks that update HP/STA/skills but not buffs.

**Key observation**: round 13 of the prior /loop replaced the snapshot-construction path with `copy.copy(self._state)`. Shallow copy preserves list-field references — so `gs.self_buffs IS` the same list object as the previous snapshot until the bridge actually pushes a fresh `self_buffs=...` kwarg.

**Fix**: identity-compare `gs.self_buffs is self._last_self_buffs_ref`; skip the `update_buffs` call when the reference is unchanged. Saves ~10-20 µs per skipped call → roughly **300-1000 µs/sec** off whichever thread the listener fires on (recognition tick on main, bridge thread otherwise).

Identity semantics verified via a 3-step state_mgr test:
- Update `self_buffs` once → reference A.
- Update HP only (no buff kwarg) → reference A preserved (same object).
- Update `self_buffs` again → reference B (new object).
